# Agent 消息增量渲染设计

## 目标

流式输出期间保持 Agent 气泡、Markdown 正文块和思考块的 Swing 组件身份稳定。普通 token 只能更新现有组件内容，不允许删除并重建整个正文。时间戳继续位于气泡外，消息列表的顶层 Row 间距统一为 8px。

## 当前问题

- 每个流式 UI 批次都会清空 Agent 正文、重新解析累计 Markdown 并创建全部子组件。
- 同一批次随后进行宽度约束，又触发一次相同的全文重建。
- 完成阶段再次清空正文和时间戳容器。
- 每个 reasoning 增量都会从消息容器删除旧思考块和 spacer，再创建新组件。
- 消息间距由多个回调分别插入 spacer，所有权分散。截图上方还包含外置时间戳行，因此从彩色气泡边缘测量会比下方更宽。

## 设计

### 稳定 Markdown 正文

Agent 气泡持有一个 Markdown 正文会话。会话把文本解析为有限的块类型：段落、标题、列表项、引用和代码块。每个块对应一个稳定 BlockView：

- 块类型和位置不变时，只更新组件内容。
- 新块只在尾部创建一次。
- 块类型因流式语法闭合而变化时，只替换变化位置之后的尾部块。
- 已完成的前缀块永远复用。
- 连续代码块改变分组或面板跨越 500px 阈值时，可以重新挂载已有组件，但不得重新创建代码编辑器。

解析累计文本仍允许从头执行，因为当前 Markdown 语法规模很小；组件协调必须是增量的。这样优先彻底消除 Swing 组件抖动，同时避免引入复杂且容易出错的完整流式 Markdown 解析器。

### 内容与宽度分离

内容更新、流式状态、宽度约束是三个独立操作：

- token 到达只更新 Markdown 会话。
- 宽度不变时，宽度约束直接返回。
- 宽度变化只更新换行宽度和组件尺寸，不重新解析或创建正文组件。
- 流式光标是正文之外的稳定组件。
- 时间戳标签创建一次；完成阶段只更新文本和可见性。

ChatPage 只在创建流式气泡和视口尺寸变化时执行宽度约束，不再在每批 token 后扫描全部消息。

### 稳定思考块

思考块使用独立 Handle，保存外层组件、正文、耗时标签和展开状态。reasoning 增量只追加正文并更新时间，不再从消息列表删除和重新添加组件。

### 统一 Row 间距

消息列表通过唯一入口添加顶层 Row。入口负责在 Row 之间插入一个 8px spacer；各事件回调不再自行管理 spacer。

“气泡 + 外置时间戳”属于同一个 Row。验收间距时，以完整 Row 底部到下一 Row 顶部为准。由于时间戳必须在气泡外，从彩色气泡边缘测量时，上方仍会额外包含时间戳高度，这是明确且一致的结构，不补伪造的时间戳占位。

## 兼容性

- 保留当前 Markdown 外观、代码高亮、代码滚动、宽屏连续代码块并排和窄屏垂直排列。
- 未闭合代码围栏继续按普通段落显示；闭合时只转换尾部块。
- 历史消息和最终消息使用同一套 BlockView 渲染。
- 流式完成后复用同一个 Agent 外层组件和未变化的正文块。

## 验证

- 连续 token 更新后，段落组件身份保持不变。
- 新增后续块时，已完成前缀块身份保持不变。
- 相同宽度和不同宽度约束均不创建新的正文块。
- 完成阶段不替换正文块，只隐藏光标并显示外置时间戳。
- reasoning 多次更新后外层组件身份保持不变。
- 顶层组件序列始终由 Row 与单个 8px 间隔交替组成。
