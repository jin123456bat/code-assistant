# Agent 气泡单一所有者设计

## 问题

同一条 Agent 消息目前会经历三套组件生命周期：流式阶段反复删除并重建临时气泡，完成阶段删除临时气泡并创建最终气泡，恢复历史会话时再次创建气泡。同时，`ChatBubbleRenderer`、`ChatPage.updateBubbleMaxWidths()` 和动画包装器都会修改组件尺寸。气泡内部结构变化后，外部宽度算法仍按固定层级寻找目标组件，因此局部样式调整容易在另一种生命周期中再次失效。

当前工作区中尚未提交的 Agent 气泡结构改动还把圆角背景与左侧蓝条拆成两套互不裁切的绘制机制，直接造成视觉回归。时间戳位于气泡外是明确的产品要求，不属于问题。

## 设计

- `ChatBubbleRenderer` 创建并持有稳定的 Agent 气泡行、圆角卡片、Markdown 内容区、时间戳和流式光标。
- 流式 token 到达时只更新稳定气泡内部的 Markdown 内容，不从 `messageContainer` 删除或重新添加气泡行。
- 最终 Agent 消息直接完成同一个流式气泡：停止光标、更新最终内容，并在气泡外显示时间戳和 token 信息。
- 历史 Agent 消息通过同一组件实现直接创建为完成态。
- 圆角、背景和左侧蓝条恢复为同一个有边框的卡片，避免两套互不裁切的绘制机制；时间戳保持在卡片外。
- `ChatPage` 只计算允许的最大宽度，然后调用 `ChatBubbleRenderer.constrainWidth()`；组件树目标选择和内部尺寸更新由 Renderer 负责。

## 范围

- 修改 `ChatBubbleRenderer.kt` 与 `ChatPage.kt` 的 Agent 气泡生命周期和宽度委托。
- 更新对应的 Renderer/Page 回归测试。
- 不修改用户气泡、工具卡片、思考块的视觉设计。
- 不处理当前工作区中与聊天气泡无关的 dispose、TabBar 或 completion 改动。

## 验证

- 流式多次更新保持同一个顶层组件实例。
- 最终消息复用流式组件，并在气泡外恢复正式时间戳/token 行。
- 历史、流式和最终状态使用相同的圆角卡片与左侧蓝条结构。
- 宽度变化通过 Renderer API 生效，`ChatPage` 不再遍历并猜测内部层级。
- 运行目标测试、完整测试、插件构建，并在测试 IDE 中检查流式回复和历史回复。
